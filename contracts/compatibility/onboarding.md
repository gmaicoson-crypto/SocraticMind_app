# 新主题流程的移动恢复协议

提供方：本仓库 `backend/routers/agent.py`。新增新主题专用取消路径，数据库 schema 未改变。
共享的七种合成状态见 [onboarding-runs.json](../fixtures/onboarding-runs.json)，由真实服务与 HTTP 投影的定向测试核验。双端领域解析与 HTTP 消费者已接入，表单状态、恢复日志与宿主页面尚未接入，不能称为三方功能验收完成。

## 创建与恢复

- `POST /api/agent/onboarding` 新增可选 `run_id`，类型为 UUID v4。新客户端在提交前持久化这个标识，并要求响应 `run_id` 与之相同；首次创建与重放均返回 201。
- 不提供标识时仍由服务端生成，每次创建一个流程，保留旧客户端行为。旧后端会忽略未知字段并生成另一 ID；新客户端不能据此宣称具备恢复能力或自动再次创建。
- 服务端在模型调用前将流程、参数摘要及 `processing=true` 一起提交，并在提交前固定创建方持有的版本快照，避免提交后刷新到他人的取消版本。数据库主键裁决并发创建，只有创建成功者调用模型；竞争失败的事务先 rollback，再读取已存在流程。处理遵循 [SQLAlchemy 的失败事务恢复约定](https://docs.sqlalchemy.org/en/20/orm/session_basics.html#rolling-back)。
- 同账号、同标识、同规范化创建参数：返回该流程当前状态。比较的是不可变的创建参数摘要，后续编辑不改变它。摘要覆盖模型 ID / session ID 和业务参数，不包含密钥；不会因重放重新调用模型。
- 同标识改换创建参数返回 `409 AGENT_REQUEST_CONFLICT`；他人拥有的标识或其他类型的流程返回 `404 RUN_NOT_FOUND`，不透露内容。UUID 不是访问凭证，所有读取和修改仍要求当前账号拥有流程。
- `GET /api/agent/runs/{run_id}` 为恢复入口。新增 `input` 为当前新主题表单字段，排除模型配置、session ID 和内部状态；其他流程类型或历史参数不再满足必填约束时为 null；不伪造合法表单，也不因此阻断整个 run 的读取 / 取消。新增 `processing` 显示是否正在处理，旧字段继续保留。
- 已保存的 run 不等于 App 已拿到响应。超时后先 GET 原标识；404 不能证明在途 POST 永远不会到达，不能立即丢弃标识并用新 ID 自动重发。用户选择退出时调用下述专用取消入口，确认取消后才清除恢复日志，再由用户明确开始另一流程。

创建端点仍先校验当前模型配置。模型后来被删除时，POST 重放可能被模型检查拒绝；GET 不依赖模型可用性，应作为恢复首选。模型调用仍为同步请求，不新增任务队列、租约或后台自动恢复。

## 未知创建的安全取消

`POST /api/agent/onboarding/{run_id}/cancel` 要求已登录账号和 UUID v4，不要求 body、模型配置或原始表单。它只处理本账号的新主题流程，其他账号或流程类型统一返回 404；已完成流程返回 409，不撤销主题或计划。返回 200 后仍须核对响应 ID、类型和 cancelled 终态。

- 尚无 run：保存 version=1 的 cancelled 记录，state 仅含 creation_cancelled=true 和 processing=false；不保存目标、回答、模型 / session ID，不调用模型。input / preview / result 为空，见 [取消样例](../fixtures/onboarding-cancellation.json)。
- 已存在 run：在原行锁和状态机内取消，版本加一；已经 cancelled 时返回原版本。普通流程保留原创建摘要检查，不因新增入口允许同 ID 改换创建参数。
- 取消占位先于创建：后续创建通过原有请求 / 模型校验后，无论表单是否改变，都返回该 cancelled 占位，不生成问题或预览。即使创建方持有旧的“不存在”数据库快照，主键冲突也会使其 rollback 并读取取消记录。
- 创建先于取消占位插入：取消方主键冲突后 rollback，再加锁读取并取消已创建流程。模型已开始时，迟到成功 / 失败仍受原版本条件写入保护；取消不保证停止上游计费。

创建和取消共用 AgentRun 主键仲裁，不对不存在的行执行锁定查询。重复取消或取消响应丢失后，可 GET 或再次取消相同 ID 核对；未获确定终态前不删除客户端日志。服务端取消记录不能按客户端日志清理而删除，否则延迟 POST 可能重新创建；当前不设置自动过期，代价是每次未知创建取消会保留一条最小记录。账号删除仍按现有外键规则处理。

旧 `/runs/{run_id}/cancel` 仍只取消已存在流程，不具备创建占位能力。新客户端需接入新路径；只通过旧接口的测试不能代表未知创建恢复已完成。

## 版本与终态

| 操作 | 当前约定 |
| --- | --- |
| 回答 | 继续必填 `step_id / version / answer`，过期步骤返回 409；响应丢失后 GET 核对，不自动再答一次 |
| 修改 | PATCH 新增可选严格整数 `version`，在持有 run 行锁后验证；至少有一个业务字段，goal / daily_minutes / timezone 不可显式 null，target_date 可 null 清除 |
| 确认 | 继续必填 `request_id`，新增可选严格整数 `version`；尚未完成时拒绝旧版本，已完成时返回同一结果，重复确认不创建另一主题或计划 |
| 重试 | POST `/retry` 接受可选 JSON `{ "version": n }`；失败且允许重试时才执行，过期版本拒绝；不带 body 的旧调用保留 |
| 取消 | 取消同一已取消流程返回现状，不再增加版本；已完成不能取消；取消后的迟到生成受原有版本条件写入保护 |

version 不接受布尔值、浮点数、数字字符串或负数。为兼容旧客户端，省略或 null 仍不启用新校验；新客户端必须提交当前版本。确认的 request_id 属于该 run，不提供跨 run 的全局去重保证。

重试 / 取消共用评估流程入口，因此评估也使用对应版本校验与取消重放，保留其 assessment attempt / mastery 的事务拥有者。未给已有主题的 plan-runs 增加创建标识，不承诺该入口具有新的创建重放能力。

服务进程中断后 processing 可能长期为 true。当前安全恢复方式是读取后由用户取消，再明确新建；不静默触发另一轮模型请求。取消用于阻止旧结果写入，不能保证上游模型停止计费。该限制需在原生恢复 UI 和后续运行验收中保留。

## 原生消费者边界

Android / iOS 请求层共用 [onboarding-wire.json](../fixtures/onboarding-wire.json) 检查实际方法、路径、body、HTTP 错误及非法原始 JSON。七种状态分别投影为处理中、诊断、预览及终态类型；UUID v4 使用规范的小写形式。新客户端要求响应 processing 字段、匹配的 run ID 和类型，不将旧后端忽略创建 ID 的响应视为成功恢复。

响应遵循已有 1 MiB 传输预算；解析还限制节点 100、安排 1000、步骤 20、版本 0 至 2147483647、结果 ID 1 至 9007199254740991。文本按 Unicode scalar 计数，节点 key 按 UTF-8 区分，日期限定公历 0001 至 9999 年。预算不是扩大提供方生成范围的承诺；超出预算返回协议错误，后续状态层须保留已保存的 ID 供核对 / 取消。未知字段忽略，未知错误 code 降为通用错误，不透传 message。

请求层支持显式可选模型 ID，不配置模型服务、保留密钥或自动重放请求。稳定确认 ID、账号 revision、journal 和 UI 按钮限制尚待状态层接入。提供方已支持取消占位，双端当前请求层仍使用旧取消路径；接入新路径及恢复状态后，才能完成未知创建安全退出验收。GET / 旧 cancel 404 本身仍不是清理日志的依据。

## 复用与权衡

复用现有 AI agent 的 on_usage、受限工作池、SSE 错误帧、请求状态、消息元数据、取消与恢复事务。新增 chat_feedback 负责安全错误分类和有界报告，chat_message_metadata 负责 web / usage 纯投影；后端路由继续编排，lifecycle 继续拥有事务，不复制凭证或创建另一份会话状态。

有效用量随回答保存，失败重生成由请求状态独立读取；不改表结构、不估算费用。状态多一次有界主键读取，历史无新增逐条查询。代价是没有流中实时计数，取消即时回读也可能早于最后保存；缺失或不一致报告显示未知。协议及兼容边界见 [回答反馈契约](../contracts/compatibility/chat-feedback.md)。

已有大文件按职责减量：聊天路由 1169 → 1146 行，lifecycle 806 → 803 行，登记上限同步下调。最后检查点新增轮次判断仍保留在唯一事务拥有者中；不为满足行数另建事务或机械拆方法。两个历史文件仍高于常规上限，继续保留有期限的来源例外。

## 双端反馈与展示

复用 ChatTurnAPI 的身份校验、HTTPTransport 的响应上限与不自动重试策略、StoredChatMessage 元数据、ChatTurnReceipt 和消息组件。可空 feedback 为现有 DTO 的默认扩展，不改变 journal 的仅标识结构或取消 / 恢复拥有者。Swift 复用 Foundation 的数值类型读取和严格 DTO 解码：用量的原始数值类型单独核对，无效可选反馈降级为未知，身份 / 状态 / 消息 ID 仍严格校验。代价是受现有响应体上限约束的额外一次解析；数值无法表示时，该响应的用量保守降级，不阻断恢复。Kotlin 私有构造和一致 copy 可见性保持受校验对象边界。

ChatAnswerFeedback 归一有效用量和本地安全错误文本，ChatTurnOutcome 只投影已确认的结果提示。未知代码不保留原文，完整回答忽略过时错误；旧失败 / 中断记录没有代码时仍提示未完成。实时错误不会直接完成请求，状态确认优先于流中提示，不自动重发。失败重生成的提示展示该次尝试用量，继续保留原回答与独立草稿；换会话 / 账号沿用现有清理机制。

Compose / SwiftUI MessageFeedback 控件复用于消息组件，错误直接可见，用量按需展开并解释范围，减少长对话默认展示的信息量。缺失用量显示未知，有效零值明确显示 0；不用计数推算费用或剩余额度。控件布局、无障碍、键盘及真实生命周期仍待宿主 / 设备验收。

双端各新增九项测试，遍历共享 15 组用量、13 组错误和九组原始 JSON 字节样例，覆盖状态 / 历史 / 取消、旧接口、错误正文不透传、终态优先、失败重生成和无自动重试。最终受影响集合 Android 29 类 209 项、Swift 29 suite 210 项及工具 86 项通过。共享回环传输新增原始字节响应，因此按影响扩展 HTTP、账号、历史及发送消费者；仍执行命名集合，不运行后端或设备测试。初轮 Kotlin 私有 data class copy 编译警告已使用一致可见性处理；影响图旧精确清单补齐反馈消费者并通过，无删断言。专用提交审查发现 iOS 会接纳 42.0 为整数、1e400 会阻断状态响应，原冻结清单已撤销并保留。修复扩展到状态、取消与历史读取，实际 HTTP 回归验证小数 / 指数计数为未知、极值整数和零值精确保留、错误身份 / 状态 / 消息 ID 仍拒绝。最后修复一处测试嵌套 require 宏编译错误后定向验证通过，失败日志保留。

固定格式 / lint 覆盖 Kotlin 九、Swift 十二、Python 六个变化文件。终态提示提取后 Android 控制器 462 → 433 行，Swift 状态模型 340 → 331 行；仍是单一会话事务拥有者，保留预警审查。XcodeGen 只登记新增视图，不构建应用。M2-05、P12、M2 与成品交付仍未完成，真实可用模型与宿主 / 设备证据继续保留为验收项。

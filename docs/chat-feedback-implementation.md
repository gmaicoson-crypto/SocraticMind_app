# 回答错误与用量实施

更新：2026-10-25，M2-05 提供方阶段。用户选择稍后配置模型服务，本批使用合成报告和模型异常，不调用真实服务。

## 复用与权衡

复用现有 AI agent 的 on_usage、受限工作池、SSE 错误帧、请求状态、消息元数据、取消与恢复事务。新增 chat_feedback 负责安全错误分类和有界报告，chat_message_metadata 负责 web / usage 纯投影；后端路由继续编排，lifecycle 继续拥有事务，不复制凭证或创建另一份会话状态。

有效用量随回答保存，失败重生成由请求状态独立读取；不改表结构、不估算费用。状态多一次有界主键读取，历史无新增逐条查询。代价是没有流中实时计数，取消即时回读也可能早于最后保存；缺失或不一致报告显示未知。协议及兼容边界见 [回答反馈契约](../contracts/compatibility/chat-feedback.md)。

已有大文件按职责减量：聊天路由 1169 → 1146 行，lifecycle 806 → 803 行，登记上限同步下调。最后检查点新增轮次判断仍保留在唯一事务拥有者中；不为满足行数另建事务或机械拆方法。两个历史文件仍高于常规上限，继续保留有期限的来源例外。

## 本批验证

- 固定格式 / lint、变化文件行数和结构检查；精确范围及原始日志保存在 `.tools/chat-feedback-provider-*`。
- 后端受影响集合 212 项、工具 78 项通过，OpenAPI 58 路径保持一致。涵盖 SDK / HTTPX 超时、限流 / 额度、错误脱敏、报告类型 / 范围、重复和晚到回调、状态 / 历史 / 重放、失败重生成及账号隔离。
- 后端状态语义影响现有双端历史 / SSE / turn 消费者及其依赖，按显式集合验证兼容：Android 26 类 213 项、Swift 26 suite 200 项通过。原生页面还没有接入反馈展示，不能把兼容性测试计为功能验收。
- MySQL 隔离实例的五个显式用例完成；其中新用例首次发现普通读取会看到旧快照，改为加锁当前读取后单独复跑通过。对应生命周期八项复跑通过；其余已通过集合未无故重跑。

首次 SQLite 用例揭示取消后新轮次未阻断旧检查点，补充轮次检查；随后 MySQL 暴露快照差异。两次失败和修复后的证据均保留。CI 初始影响测试有两个清单不匹配，收窄依赖传播并为共享反馈持久化显式补齐相关消费者；未去掉断言或改成全量测试。

本批没有 APK / IPA / iOS 模拟器应用构建、设备测试、真实模型、外部部署、远端 CI 或 push。下一步接入双端安全反馈、用量展示和定向测试。M2-05、P12、M2 与成品交付均未完成。

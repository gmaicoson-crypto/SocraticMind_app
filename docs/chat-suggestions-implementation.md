# 上下文建议

更新：2026-10-24。双端建议核心、共享契约和页面接线已实现并通过定向主机测试。当前应用仍未重新构建；真实模型质量、延迟和原生交互尚待验证。

## 获取与发送建议

普通新会话先显示本地参考话题；已有对话或知识节点上下文可自动请求建议。点击“换一批”显式读取下一批，并排除当前显示的内容。AI 返回与服务端 / 本地参考话题使用不同标签，网络失败保留可用的参考话题，不自动重试模型调用。

点击建议沿用固定源项目的直接发送行为。若输入框已有草稿，先确认“替换草稿并发送”；取消保留原文。确认期间草稿、账号或会话改变后，旧确认不能覆盖新草稿。发送中的重复点击不会产生第二个请求。普通聊天入口已接线；知识节点的目标参数与默认话题已准备并验证，节点页面仍按 M3 实施。

## 复用与扩展

复用固定上游 `4a20228e630168113e9e09a66de83699545fa82c` 的建议行为与本地默认话题、现有 backend GET `/api/chat/suggestions`、HTTPTransport、SessionStore、ChatLibrary 和 ChatTurn。没有新增依赖、数据库迁移或后端生产代码变更。Vue 状态逻辑作为行为参考，没有迁入原生工程。

| 职责 | 组件 | 边界 |
| --- | --- | --- |
| 请求与响应 | ChatSuggestionsApi / ChatSuggestionsAPI | 复用有限 HTTP 请求与重复查询参数；不管理页面或账号凭证 |
| 上下文与缓存 | ChatSuggestionsState、ChatSuggestionDefaults | 最近相关消息摘要、默认话题及有界内存缓存；不持有历史副本 |
| 读取与选择 | ChatSuggestionsController / ChatSuggestionsModel | 管理建议任务、展示状态与草稿确认；不另建发送协调器 |
| 最终发送 | 既有 ChatTurn | 原子检查账号、目标和预期草稿，再走现有持久请求记录 / SSE / 停止 / 恢复流程 |
| 原生展示 | ChatSuggestionsBar | 显示横向建议、“换一批”和确认弹窗；不处理令牌或网络字节流 |

这样建议发送可继续使用稳定请求 ID 和既有恢复能力，后续节点聊天能复用同一接口与组件。代价是增加一个独立的建议状态对象，以及发送协调器中的原子比较入口；不能把“替换输入再发送”拆成两个无保护的操作。

## 协议和资源预算

- GET 保留 mode、session_id，知识节点带 topic_id / node_key；可选 model 作为上下文的一部分。当前页面采用服务端默认模型，模型设置页尚未实现。
- exclude 使用重复查询参数，最多 24 项，trim 后按 Unicode 标量截取 80 个并去重；特殊字符和 emoji 由既有 URL 编码处理。
- 返回最多 12 项，拒绝空白、重复、非字符串和未知来源。每项最多 5000 个 Unicode 标量，总建议正文最多 64 KiB UTF-8；未知或超限响应降级为参考话题。
- 上下文包含账号及登录 revision、目标、模型，以及最新 6 条相关、非空、已完成 chat 消息的 SHA-256。每条只摘要末尾 800 个 Unicode 标量及 ID / role；键中不保存聊天正文。打字不会改变这个摘要或触发新请求。
- 只缓存非空 AI 结果；最多 30 个上下文，缓存建议正文合计最多 64 KiB，超限按 LRU 回收。该预算不包含语言对象的固定开销。退出 / 换账号清空，不写磁盘；重启后需重新获取。
- 每个上下文首次自动读取至多一次；显式刷新可以再读。可见性关闭会取消进行中的读取，返回前台可重新发起被取消的读取。网络失败后保持参考话题，等待显式刷新。
- 原后端在新会话返回参考话题时可能忽略 exclude；客户端再次过滤显示过的项，并从本地话题池选择替代项。有限话题池可能在多次刷新后轮换回旧项，不承诺无限不重复。

本地上下文摘要用于判断建议是否需要刷新，不是后端消息上下文的快照或事务。后端仍按自身规则读取已保存消息；前后端分页边界、真实模型延迟与多设备更新另行验收。

## 取消与迟到结果

读取同时受账号 revision、上下文和任务序号保护；即使网络请求忽略取消，旧结果也不能覆盖新账号、会话或模型。当前 401 通过 SessionStore 失效流程清理建议，旧账号 401 不会退出新账号。

历史刷新、发送占用、删除占用或页面不可见时禁用选择。选择已有草稿会取消当前建议读取，避免弹窗内容被迟到响应替换；取消确认后的“换一批”仍携带当前显示项作为排除集合。iOS 在确认回调中先保存用户选择，再等待账号核对，避免系统关闭弹窗时清理绑定导致确认丢失。

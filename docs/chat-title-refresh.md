# 自动标题更新

更新：2026-10-24。双端核心和页面接线已实现；本阶段没有重新构建应用，设备行为仍待验证。

## 复用与职责

后端普通聊天已在首轮消息写入时安排标题任务，并由既有 worker 维护租约、失败重试和手动标题优先级。本批复用 GET `/api/chat/session-titles`，不增加标题生成服务、数据库迁移或模型调用入口，也不替旧历史自动创建任务。

ChatActionsApi / ChatActionsAPI 同时提供只读 ChatTitlesGateway；单条 title 方法委托批量 titles。ChatLibrary 继续作为账号历史的唯一状态所有者，增加独立标题读取任务；ChatTitleRefresh 文件只定义读取能力、候选选择和标题投影，不拥有凭证、任务或另一份历史。修改动作、发送协调器及原消息组件继续复用。

这样一次请求可更新多个会话，且不重读消息正文。代价是 ChatLibrary 多维护一条有界读取通道和可见性状态；它只能显示后端已经生成的标题，不能保证模型在本轮读取预算内完成。

## 协议与读取预算

- 批量接口接受 1—100 个不同会话 ID，通过重复的 `ids` 查询参数传递；URL 编码保留中文、emoji、空格、`/ ? & # +`。公共传输层新增重复参数入口，禁止单值与重复参数使用同一个键。
- 返回结果可以无序、可以只包含部分 ID；拒绝重复结果、未请求的 ID、非法标题状态及 retry_pending 类型。缺失 ID 表示本轮没有可读标题，不推断任务成功，也不创建任务。
- 候选包含已加载摘要中非 ready / manual 项；当前打开的会话优先，即使刷新后它已不在最新一页。翻页后的批次优先新加载页，每批最多 100 个 ID。
- 一轮立即读取一次，此后最多等待 500、1000、2000、4000、8000、8000、8000 毫秒再读，共最多 8 次。后续只读 pending、running 或 failed 且 retry_pending 为 true 的 ID。
- ready、manual、无重试的 failed 和缺失 ID 从当前轮移除。失败或预算耗尽显示刷新提示；现有标题 / 历史保持可用。网络错误不在同一轮自动重试。
- 这些限制约束请求次数和等待间隔；总耗时仍包含每次网络响应时间。每次请求沿用公共传输层的有限请求配置，不能把间隔之和当成整体超时。

首次会话读取完成、用户刷新 / 翻页、打开另一个已有会话或页面重新可见，可以启动新一轮；重复的同值可见性通知不会重置耗尽预算。Android 用宿主 Lifecycle 的 STARTED 可见状态，iOS 用 scenePhase.active；离开页面或进入后台时取消标题读取。UI 不直接发网络请求。

## 迟到结果和账号边界

| 场景 | 处理 |
| --- | --- |
| 新会话摘要读取 | 先使旧标题读取失效；摘要成功后再启动新批次，避免旧摘要覆盖新标题 |
| 手动改名 / 删除成功 | 先取消旧标题读取，再沿用动作投影；迟到自动标题不能改回手动值或恢复已删除行 |
| 打开较早会话 | 优先读取当前会话；刷新最新一页后仍更新其页头，但不把它强行插回摘要列表 |
| 退出 / 换账号 | 清除全部读取；账号 ID、登录 revision 和任务序号共同隔离结果 |
| 当前 401 | 复用 SessionStore 失效处理，清空历史；旧账号 401 不影响新登录 |
| 取消后仍返回 | 即使网络替身忽略取消，任务序号和账号检查仍阻止旧成功 / 失败写回 |

本机读取隔离不提供跨设备事务或服务端任务完成保证。标题 worker 的真实耗时、设备网络切换、后台恢复、真实模型及多进程竞争仍需单独验证。

## 定向验证与规模

双端新增标题状态测试各 11 个测试方法，旧账号用例覆盖成功及 401；包括批量缩小、8 次预算、显式刷新、可见性切换、手动标题优先、删除、新摘要覆盖顺序、当前账号失效、离线、100 项上限，以及已打开旧会话不在最新一页时的更新。

共享样例及回环 HTTP 测试验证重复参数和无序子集；后端增加真实路由的合成账号批量读取 / 归属 / 100 项上限契约。新增公共查询能力会影响账号、历史、发送及标题接口消费者，CI 按显式依赖扩展这些集合。格式检查只针对变化文件，未运行全量测试或应用构建。

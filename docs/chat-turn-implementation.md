## 使用与状态

登录后先读取当前账号的待确认请求，再允许新建或选择对话。新建只产生会话 UUID，首次发送才在服务端产生消息。输入保留原始空白、换行与代码缩进；上限为 5000 个 Unicode scalar，与 Python 长度规则对齐，超限禁用发送，不静默裁切。草稿只在当前页面内存中保留，返回时确认放弃；没有自动保存未发送正文。

1. 发送前生成稳定 request_id，将账号、会话目标和请求 ID 写入恢复记录并验证可读；保存失败时不 POST，草稿保留。
2. 同账号一次只允许一个待确认请求；发送、停止或核对期间不能另起请求。Token 仍由 SessionStore 的账号 revision 租约持有，不进入页面状态和磁盘记录。
3. 收到 msg_ids 后按稳定 ID 隐藏重复历史行，显示当前输入和活动回复。文字最多约每 50 ms 发布一次状态，身份变化和结束时立即刷新；不逐字重新解析 Markdown。
4. 流结束、断线、超时或收到 DONE 后，用 GET 查询同一 request_id；不会自动重放 POST 或生成新 ID。查询最多首次加 3 次延迟重读，仍在生成则显示“核对状态 / 停止回复”，避免无限轮询。
5. 停止调用服务端持久取消接口；取消本机网络任务不等于服务端已停止。取消失败保留记录并显示未确认；若服务先完成，按实际 complete 处理。
6. 确认终态后通过历史接口读取实际消息，再清理恢复记录、交给历史状态按 ID 合并。历史所有者确认接收后才允许下一次发送，避免观察流合并更新时漏掉完成结果。

`404 CHAT_REQUEST_NOT_FOUND` 表示尚不能证明请求是否到达，保持未确认。用户可再次查询，或停止以建立服务端取消标记；后到的相同请求会被拒绝。`409 CHAT_REQUEST_DELETED` 表示原请求已删除或被替代，按不可用终态处理并刷新历史。其他 409 不冒充删除或成功。

当前停止 / 核对允许用户显式重试，后端取消端点具备幂等语义；网络层仍不自动重试写入。当前账号的 401 清空页面，旧账号的迟到成功或 401 不影响新账号。退出会取消本机 IO、清空正文与页面状态，保留不含正文的恢复标识；同账号再次登录可查询仍未确认的请求。

## 复用与职责

| 位置 | 责任 | 复用与边界 |
| --- | --- | --- |
| ChatTurnModels / ChatTurnAPI | 目标、请求、终态、发送 / 查询 / 取消适配 | 复用 HTTPTransport、ChatEvent、现有后端；不保存凭证 |
| ChatTurnController / ChatTurnModel | 当前账号的草稿、活动请求、任务序号及恢复流程 | 复用 SessionStore；一处拥有状态与取消顺序 |

| ChatLibraryController / ChatLibraryModel | 已保存历史与分页、结果合并 | 新 ChatConversation 表示未持久化目标；不伪造 message ID |
| ChatComposer / ChatComposerView | 输入、计数、发送、停止、核对与状态提示 | 页面不直接操作 Token、SSE 字节或磁盘 |
| MessageContent / MessageContentView | 已保存与活动消息的公共布局、复制 | 完成后复用 Markdown；活动文字暂用纯文本预览 |
| AppViewModel / AppModel | 绑定账号、导航与结果交接 | 恢复目标自动打开；合并完成结果后显式 acknowledge |

好处是聊天与后续节点模式可复用目标、发送协议、存储和输入组件，历史与活动内容不会各维护一份完整消息库。代价是双端各维护状态机及平台存储接线，保守恢复会暂时阻止新发送。重生成、引用、附件、模型选择和结构化扩展事件仍待接入，不能把当前普通 qa 接口当作完整 P03。

## 有界读取与持久化

恢复复用 `/api/chat/session-messages?session_id=...&snapshot_id=<id>&limit=1`，最多两次查询分别取用户消息和 AI 消息。必须同时匹配快照、会话和精确消息 ID；删除后端点可能返回更早邻居，客户端不会拿邻居冒充原结果。角色、模式、节点和正数 ID 也要验证。部分消息已删除时保留可用结果并提示刷新。

恢复文件按规范化 endpoint scope 的 SHA-256 分目录、按用户 ID 分文件，限制 4096 字节、带版本并校验内容归属。Android 使用 noBackupFilesDir、文件同步与同目录原子替换；Swift 用应用私有 Application Support、原子写入和同步，设置备份排除，iOS 设置首次解锁后可访问的文件保护。文件 IO 离开 UI 线程。仅保证本批测试覆盖的主机重开、隔离及故障行为；真机进程终止、锁屏、备份、卸载和断电均未验证。

不同未确认请求不能覆盖原记录，清理时比较完整引用，旧任务不能删除新请求。记录损坏、读写或清理失败时禁止新发送并允许重读，不静默删除。清理报错时仍把已经确认的结果交给历史；即使删除实际已生效，也不会丢失当前内存中的完成结果。持续损坏需要诊断原请求与服务状态；当前尚未提供用户自行修复损坏文件的界面。

活动回复保留最多 512 KiB UTF-8；超限停止本机读取并查询服务器，不能把裁切文字当成成功结果。UI 临时预览最多 32 行，可复制当前完整已接收文字；已保存的完整正文使用既有受限 Markdown 投影。这样减少流式布局和缓存抖动，但生成中没有富文本排版，完整内容还受 HTTP 有限响应预算约束；设备内存、帧率与滚动跟随尚未测量。

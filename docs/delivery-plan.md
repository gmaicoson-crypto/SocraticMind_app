# 双端内测成品交付计划

更新：2026-10-22。用户已授权分阶段实现完整双端 App，并确认当前本地开发、不上线。显示名 SocraticMind，开发标识 com.gmaicoson.socraticmind，最低 Android 8.0 / iOS 17。实际结果见 [实施状态](execution-status.md)。

## 成品的定义

交付的是两端可用的学习产品及其运行服务。用户能完成注册、创建学习主题、规划、节点学习、评估和复习，也能使用普通对话、附件、统计和本地笔记；后台中断、弱网、账号切换和版本升级有明确行为。完整范围见[产品范围与验收](product-scope.md)。

| 交付部分 | 必须具备 | 完成证据 |
| --- | --- | --- |
| Android | 本地应用可运行，按明确构建要求进行安装 / 升级与学习流程验证 | 包摘要、签名标识、版本、安装与定向真机验收记录 |
| iOS | 本地 Xcode 工程与模拟器运行；真机安装按实际账号和设备条件验证 | 构建号、运行方式、实际设备 / 模拟器及未验证限制 |
| backend | 本仓库维护的服务可在本地持久运行，并被模拟器 / 指定设备访问 | 服务版本、迁移版本、运行配置说明、健康与真实联调记录 |
| 数据与运维 | 独立数据库、持久附件、备份恢复、日志、用量限制和故障处置 | 恢复演练、告警验证、依赖到期与版本更新记录 |
| 代码与协作 | 可从源代码复现工程，固定依赖，实际运行的增量质量 CI | 源提交、工具链清单、对应 CI 链接、来源与许可证 |
| 使用交接 | 安装升级指引、已知限制、反馈入口和维护责任人 | 用户指引、验收结果、未解决问题与处理计划 |

Android 和 iOS 必须使用同一组验收语义；允许平台界面不同。单端完成、mock 演示、核心包单测通过或仅生成安装包，均不能标记成品交付完成。两端同账号共享后端学习数据，本地笔记和画布不承诺跨设备同步。

本地运行仍需要保存数据、重启恢复和可复现的配置；测试用临时数据库不用于保存用户学习进度。没有付费 Apple Developer 账号不阻塞原生源码、Swift 包或模拟器工程开发。真机个人签名有期限和能力限制，不能承诺永久安装；安装验证到达相应阶段再按实际条件记录。[Apple 账号说明](https://developer.apple.com/help/account/basics/about-your-developer-account)

## 实施方式与取舍

沿用双端原生和同仓 backend。后端先按固定版本迁入，再按移动端需求独立维护；不重写已验证的学习规则。每个功能依次完成契约、必要后端调整、Android、iOS 和对应验收，阶段结束前两端必须达到同一功能范围。

这样能提前暴露接口、恢复和交互差异，也便于复用同平台组件；代价是每条用户流程都有两套原生实现和验证工作。一个人开发时可顺序完成两端，不能把一端的通过记录复制给另一端。

先拆状态机、解析、存储和 UI，再按需要增加模块；不为规划中的全部功能预建空组件。后端迁入的大文件登记基线，随相关功能收敛。所有新代码遵守现有行数门禁，不通过降低规则完成里程碑。

## 阶段与退出条件

保留已有 M0—M5 编号，使原架构、功能矩阵和 CI 文档能继续对应。阶段是交付关口，不是六次全量测试；证据随定向变更逐步累积。

| 阶段 | 用户能够得到什么 | 主要工作 | 退出条件 |
| --- | --- | --- | --- |
| M0 范围与条件 | 清楚内测包含什么、如何安装与维护 | 范围、产品身份、设备、分发账号、资源与责任确认 | M1 所需工程标识和设备范围已确定；服务、签名等有负责人和完成节点 |
| M1 可联调工程 | 三方能围绕真实契约开发 | 后端来源迁入、双端骨架、设计规范、契约、增量质量 CI、恢复与图谱风险验证 | 定向基础检查真实通过；测试服务能运行；双端风险验证具备记录，设备项未完成时不得宣布退出 |
| M2 对话版本 | 两端账号和普通对话可持续使用 | 注册找回、登录失效、聊天历史、SSE、停止、重生成、恢复、基础模型选择 | 真实后端联调和指定设备验证通过；账号隔离、重复生成和终态问题关闭 |
| M3 学习版本 | 完成一条真正的学习闭环 | onboarding、计划、主题、图谱、节点学习、评估、掌握撤销、记忆和来源 | 新用户从建主题到完成节点并次日继续，两端及服务端结果一致 |
| M4 功能完整候选版 | 完成源功能范围的移动端表达 | 附件、资料头像、模型配置、统计成就、笔记画布、导出、完整异常状态 | 产品范围中的 V1 必交项全部有双端证据；账号删除、升级、性能和设备缺口收敛 |
| M5 本地成品交付 | 用户可安装、升级、持续访问服务并反馈 | 本地持久环境、备份恢复、明确要求后的运行 / 安装验证、反馈修复和维护交接 | 交付清单全部满足、无阻断缺陷；实际运行 / 安装方式和本地服务已验证；维护责任明确 |

M2 / M3 是内部开发里程碑，M4 是功能候选版；只有 M5 才算本次成品交付。构建与部署在对应阶段具备输入后按用户要求执行，不因本文列出步骤自动执行。

主依赖为 M0 → M1 → M2 → M3 → M4 → M5。开发身份与本地条件在 M0 确认，签名按设备验证需要落实，基础设施从 M1 准备，备份和用量保护在邀请真实用户前就绪；这些工作不能全部拖到 M5。

## 排期和工作量管理

当前未获得人员、每周投入、设备与账号条件，因此不承诺日历工期。M0 记录实际可用人日；M1 阶段完成后，用“后端启动 + 两端 SSE 验证 + 质量门禁”的实际投入校准速度，再对 M2—M5 给出范围估算。

每个任务分别记录 Android、iOS、backend、验证与运维投入，以及外部等待；复用后端仍包含迁入、环境验证和回归成本。一个人负责三方时应合计投入，不能把同时列在表中的工作当作可以同时完成。模型费用、服务器、存储、邮件、开发者账号、macOS CI 和设备是单独预算项。

每个阶段开始前确认范围、依赖、负责人、预计投入与外部条件；结束时核对证据、剩余风险和下一阶段估算。新增需求先判断属于已有验收缺口还是范围扩展，后者必须更新范围及依赖，不静默挤占既定必交项。

## 最主要的交付风险

| 风险 | 提前验证 | 不能采用的“完成”判断 |
| --- | --- | --- |
| 原后端迁入后不能独立运行 | M1 核对根配置、依赖、迁移、路径及隔离启动 | 复制目录即认为复用完成 |
| SSE 生命周期导致重复生成 / 历史缺失 | M1 协议验证，M2 双端后台与进程恢复 | 一次前台聊天成功即通过 |
| 图谱、Markdown、画布性能或平台能力不足 | M1 小样技术验证，M3 / M4 定向设备测量 | 主机单测成功即代表 UI 可用 |
| 模型 / 邮件 / 搜索 / 解析在目标环境不可用 | M1 固定供应与能力清单，邀请测试用户前真实小样联调 | mock 通过即代表外部服务可用 |
| 只有临时可安装的 iOS 产物 | M0 本地条件，M5 按设备验证并说明签名限制 | 单个 IPA 文件即代表所有人可以长期安装 |
| 内测使用产生费用、数据或恢复问题 | 真实用户前设置限额和备份；M5 做恢复演练 | 只确认 HTTP 服务启动 |

# 模型选择实施

更新：2026-10-25。M2-05 的提供方契约、双端模型目录与选择核心已验证，Compose / SwiftUI 选择器已接线，宿主编译与设备交互待验。用户确认「模型服务稍后配置，先继续开发」；真实可用模型、超时 / 限额 / 用量及完整 P12 仍待验收，目录存在或替身通过不能代替真实调用。

## 复用与范围

固定上游 `4a20228e630168113e9e09a66de83699545fa82c` 的 `api/models.ts`、`dialogue/ModelSelector.vue` 按系统 / 用户模型展示，并用配置 ID 选择。本仓库继续使用 `/api/llm/models` 和聊天 / 建议请求的 `model` 字段；现有用户模型 CRUD 留给 M4-03 完整管理，不在客户端重新实现服务配置或保存密钥。

- 目录按当前账号返回环境与自定义模型；环境模型不返回连接地址或凭据，所有模型均不回显密钥。自定义目录现有 base_url 字段保持兼容，基础选择只需 ID、名称、官方模型名和来源。
- 显式选择发送配置 ID；多个配置可以使用同一个官方模型，不能按 model 名称去重或定位。
- 省略 model 使用服务端默认。目录没有默认 ID 字段，列表第一项也不保证是默认；移动端应保留明确的「服务端默认」选项，不自行猜测。
- 重生成复用原问题，但可以使用当前选择的模型。稳定 request_id 的重放仍由服务端指纹和终态约束，不重复调用模型。
- GET 目录仅表明配置存在，没有探测模型健康、费用或剩余额度；不自动产生外部模型请求。

## 请求与错误边界

聊天的 ChatRequest 从大路由移到 `backend/schemas/chat_request.py`，字段、默认值、输入 / 引用 / 附件限制以及 web_mode 派生规则完整保留。路由仍导入同名类型，调用与事务顺序不变。OpenAPI 58 路径快照一致，没有新增数据库迁移或依赖。

聊天与建议共用的 selected_model 在模型不存在、越权、已删除或服务配置无法解析时，保留 HTTP 422 并返回结构化 `LLM_MODEL_UNAVAILABLE`、可读 message 和 retryable=false。该错误发生在创建 ChatTurn 之前；移动端可经现有取消接口确认停止标记后清理恢复记录，并保留输入供用户重新选择。通用 422、网络中断和生成阶段错误仍需核对，不能一概认为请求没有开始。

好处是选择失效能与生成中断明确区分，双端无需解析服务端错误文案；旧客户端仍能显示 message。代价是双端需要兼容新错误码与旧服务的通用错误，且目录刷新成功也无法保证随后调用一定可用。密钥解密、模型执行、会话占用和终态保存的原有归属不变。

文件规模：聊天路由从 1216 行降至 1169 行，历史登记上限同步下调；独立请求 schema 59 行。拆分围绕请求校验职责，未压缩语句或增加豁免；其余路由与生成编排仍待后续按职责拆分。

## 双端实现与边界

ChatModelApi / ChatModelAPI 复用 HTTPTransport 与 SessionStore，不另建网络或凭据组件；目录、配置 ID 校验和轻量选择状态留在现有 core:chat / MindCore。ChatModelController / ChatModelSelectionModel 管理目录读取与选择；已有 ChatTurnController / ChatTurnModel 持有下一次发送的选择，所有入口统一从这里快照，建议状态不再保留另一份模型 ID。后续管理功能可以复用目录类型，不提前建立空模块。

- 目录最多 256 项；配置 ID 最多 100 个 Unicode scalar，名称 / 官方模型名各最多 200 个，保留字段的 UTF-8 总量最多 256 KiB；超限、重复 ID、未知来源、错误类型直接拒绝，不静默截断。目录只保留 id / name / model / source，不保留返回的连接地址或凭据。
- Kotlin 复制并冻结列表；Swift 是值类型。ID 按原始字符 / UTF-8 比较，Swift 列表身份与建议缓存显式使用字节身份，避免将规范等价但不同的 ID 合并。
- 明确的「服务端默认」省略 model；显式选择发送配置 ID。普通发送、重生成、建议直接发送或草稿确认共用选择，已经开始的请求不随目录刷新改变。重生成继续保留原问题、引用 / 附件上下文和独立草稿。
- 目录按当前 endpoint 的 SessionStore 和账号 revision 隔离；旧读取被取消，即便替身不配合取消也无法覆盖新账号。选择和目录仅存内存，退出 / 换账号清理，重启回到服务端默认；代价是需要重新选择，不提供跨进程偏好保存。
- 刷新失败保留已有目录与选择并显示提示；初次失败仍可主动使用服务端默认。刷新成功但选中 ID 消失时保留旧名称 / ID、标记不可用，禁止新发送与建议，不自动换模型。用户可以刷新或明确选择默认 / 其他配置。
- 仅 HTTP 422 + LLM_MODEL_UNAVAILABLE 走明确的发送前拒绝处理。先调用现有取消接口形成持久停止标记；取消未确认时保留恢复记录和已提交输入。确认中断且没有消息 ID 后恢复普通输入，清理记录失败时仍保留草稿；重试核对 / 停止不再次 POST。重生成保留原回答。通用 422、其他 HTTP 状态或网络错误仍按既有状态核对流程处理。
- 恢复 journal 继续是 schema 2，仅记录请求和会话等标识；不增加提示词、模型配置或密钥落盘。输入恢复仅限当前进程，进程终止后的恢复仍只核对已提交请求。

Compose / SwiftUI 选择器展示系统模型、我的模型和独立默认项，提供刷新、空态、失败 / 失效提示，并解释提问、相关对话与附件会经后端发送给所选模型。列表采用稳定配置身份，遵循 [Compose 列表 key](https://developer.android.com/develop/ui/compose/lists) 和 [SwiftUI ForEach 身份](https://developer.apple.com/documentation/swiftui/foreach) 的官方能力；XcodeGen 2.46.0 只重新登记新增视图，没有构建应用。选择器在发送期间禁用，目录刷新不改变活动请求。

# 模型选择实施

更新：2026-10-25。M2-05 先完成模型目录与选择的提供方契约；Kotlin / Swift 模型目录、选择状态和页面尚未接入。真实模型可用性未验证，不能以目录中存在模型或替身测试通过代替 P12 验收。

## 复用与范围

固定上游 `4a20228e630168113e9e09a66de83699545fa82c` 的 `api/models.ts`、`dialogue/ModelSelector.vue` 按系统 / 用户模型展示，并用配置 ID 选择。本仓库继续使用 `/api/llm/models` 和聊天 / 建议请求的 `model` 字段；现有用户模型 CRUD 留给 M4-03 完整管理，不在客户端重新实现服务配置或保存密钥。

- 目录按当前账号返回环境与自定义模型；环境模型不返回连接地址或凭据，所有模型均不回显密钥。自定义目录现有 base_url 字段保持兼容，基础选择只需 ID、名称、官方模型名和来源。
- 显式选择发送配置 ID；多个配置可以使用同一个官方模型，不能按 model 名称去重或定位。
- 省略 model 使用服务端默认。目录没有默认 ID 字段，列表第一项也不保证是默认；移动端应保留明确的「服务端默认」选项，不自行猜测。
- 重生成复用原问题，但可以使用当前选择的模型。稳定 request_id 的重放仍由服务端指纹和终态约束，不重复调用模型。
- GET 目录仅表明配置存在，没有探测模型健康、费用或剩余额度；不自动产生外部模型请求。

## 请求与错误边界

聊天的 ChatRequest 从大路由移到 `backend/schemas/chat_request.py`，字段、默认值、输入 / 引用 / 附件限制以及 web_mode 派生规则完整保留。路由仍导入同名类型，调用与事务顺序不变。OpenAPI 58 路径快照一致，没有新增数据库迁移或依赖。

聊天与建议共用的 selected_model 在模型不存在、越权、已删除或服务配置无法解析时，保留 HTTP 422 并返回结构化 `LLM_MODEL_UNAVAILABLE`、可读 message 和 retryable=false。该错误发生在创建 ChatTurn 之前；移动端可经现有取消接口确认停止标记后清理恢复记录，并保留输入供用户重新选择。通用 422、网络中断和生成阶段错误仍需核对，不能一概认为请求没有开始。

好处是选择失效能与生成中断明确区分，双端无需解析服务端错误文案；旧客户端仍能显示 message。代价是双端需要兼容新错误码与旧服务的通用错误，且目录刷新成功也无法保证随后调用一定可用。密钥解密、模型执行、会话占用和终态保存的原有归属不变。

文件规模：聊天路由从 1216 行降至 1169 行，历史登记上限同步下调；独立请求 schema 59 行。拆分围绕请求校验职责，未压缩语句或增加豁免；其余路由与生成编排仍待后续按职责拆分。

## 双端接续

下一步复用 HTTPTransport、SessionStore、已有发送与建议状态；目录请求应有长度边界、取消与账号 revision 隔离。切换账号清理旧选择；刷新后已选配置消失时保留明确提示，不自动换到另一个模型发问。普通发送、建议确认和重生成应使用一致选择，已经开始的请求保持自己的不可变快照。

页面需要解释数据会经后端发送给所选模型，并显示加载、空态、错误、刷新与当前选择。真实模型、超时 / 限额 / 用量以及原生页面与设备生命周期仍须对应证据；模型配置管理、完整 P12 与成品目标均未完成。
